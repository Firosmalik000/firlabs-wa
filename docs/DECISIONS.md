# Decisions

## Confirmed Decisions

- The existing Laravel starter remains the foundation.
- Laravel Boost guidelines remain authoritative.
- Laravel 13, PHP 8.4, Inertia v3, React 19, and Tailwind v4 remain unchanged.
- PHPUnit is the only testing framework.
- React remains integrated through Inertia.
- Wayfinder is used for frontend route integration.
- One shared MySQL database is used.
- Tenant isolation uses `tenant_id`.
- Laravel is the source of truth.
- One GOWA instance is used for the MVP.
- Each WhatsApp device belongs to one tenant.
- GOWA device IDs are generated by Laravel using unpredictable ULIDs.
- Media uses Laravel's public filesystem disk.
- Database queue is acceptable initially.
- Automated billing is outside the MVP.
- WebSockets are outside the MVP unless already installed.
- GOWA is never exposed directly to normal users.

## Implementation Guardrails

- Do not reinstall Laravel.
- Do not upgrade dependencies without explicit approval.
- Do not replace the existing React/Inertia structure.
- Do not rework authentication unless a real starter defect requires it.
- Do not expose tenant IDs or GOWA credentials to the browser.
- Do not make the browser talk to GOWA directly.

## Phase 1 Notes

- Tenant creation, membership, and current tenant resolution should extend the existing Fortify registration flow.
- The current auth and settings starter should be reused rather than replaced.
- Super admin access should be explicit in Laravel policies and middleware, not just in the UI.

## Architecture Notes

- Keep tenant-owned queries tenant-scoped from the first tenant migration onward.
- Keep GOWA integration isolated behind Laravel services or actions.
- Keep queue jobs idempotent and safe to retry.
- Keep media storage relative-path based on the public disk.
